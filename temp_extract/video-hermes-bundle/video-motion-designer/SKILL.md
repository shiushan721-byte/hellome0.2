# Video Motion Designer

Design videos whose meaning depends on motion, visual systems, and synthetic or illustrated imagery.

Use this skill when captured footage is not the main truth source and the work must be carried by animation, diagrams, composited stills, or generated visuals.

## Inputs

Expect:
- user goal
- audience
- output spec
- style reference
- production strategy
- success definition

Helpful inputs include:
- script or outline
- brand rules
- reference videos or frames
- diagrams, decks, screenshots, or rough sketches

## Workflow

1. Choose the visual mode.
2. Build the visual system.
3. Break the piece into scenes.
4. Assign motion intent to each scene.
5. Return a feasible build plan.

## Visual Mode

Choose the dominant mode:
- `diagram-led`
- `kinetic-type-led`
- `illustration-led`
- `ui-motion-led`
- `generated-visual-led`
- `mixed-system`

Use [references/visual-modes.md](./references/visual-modes.md) to choose a mode and avoid style drift.

## Visual System

Define:
- composition language
- typography behavior
- color role
- iconography or illustration approach
- transition vocabulary
- density and pacing rules

Do not jump straight into scene ideas without first locking the system. Most animation incoherence starts here.

## Scene Planning

For each scene, specify:
- narrative purpose
- what must be understood by the viewer
- visual treatment
- motion treatment
- required assets
- feasibility notes

Use [references/scene-planning.md](./references/scene-planning.md) for a compact scene template.

## Motion Rules

- motion should reveal meaning, not decorate empty space
- use repeated transition logic across the piece
- do not mix too many visual metaphors
- if the explanation is dense, reduce visual novelty and increase structural clarity
- if visuals are generated, state what must stay consistent across shots

## Failure and Escalation

Escalate when:
- the user actually has strong source footage and only needs support graphics
- the visual ambition exceeds the likely production method
- there is no clear explanatory spine
- the request is a product demo rather than a motion-first piece

## Output

Return:
- selected visual mode
- visual system summary
- scene-by-scene plan
- asset requirements
- motion constraints and risks
